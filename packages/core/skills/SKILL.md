# SKILL: pentest(p2p 三环渗透)

## 1. 垃圾洞清单(绝对不报)
CORS 跨域配置 / Sourcemap 泄露 / 安全头缺失 / 版本号与中间件指纹 /
Self-XSS / 单独的开放重定向 / 限速缺失 / Cookie 缺少 Secure/HttpOnly(单独) /
任何没有稳定复现 PoC 的发现

## 2. 灵魂金句
现象不是漏洞,漏洞是结果。报的是结果(越权/注入/RCE),不是过程(信息泄露/配置)。

## 3. 速查卡
- 现象≠结果 | 无PoC≠漏洞 | 有可能≠已证明
- 自己看自己的数据=正常功能,不判越权
- 配置类问题→config_advisory,不算漏洞
- 20 分钟无进展→换方向,不死磕
- 每条 Finding 必须带可复现 curl 单行命令

## 4. 铁律
⛔ 仅测授权 scope 内目标(scope 门控会硬拦截,勿绕)
⛔ rm -rf /、mkfs、dd 写盘、shutdown、DROP TABLE 一律禁止
⛔ 不写 Webshell,不上传恶意文件,不做拒绝服务
⛔ PII 只取证一条样例即停

## 5. 七问验证门(报告前逐条自答)
1 在授权范围内? 2 有完整可复现 PoC? 3 需要额外假设解释危害?
4 影响已证明还是"可能"? 5 是结果还是现象? 6 开发者能看懂?
7 提交平台会接受吗? —— 任一不过,不写报告。

## 6. 决策树(不是流程)
有登录态 → 越权/IDOR 优先;无登录态 → 未授权访问/注入优先
Java 中间件 → 反序列化/JNDI;PHP → 文件包含/SQLi;Node → 原型链/SSRF
支付功能 → 竞态/金额篡改;上传功能 → 路径穿越/解析;API → BOLA/批量分配
高 ROI 顺序: 认证 > 支付 > 数据导出 > 其他

## 7. 报告格式
severity(P1/P2/P3) + title + target + type + 漏洞描述 + 影响 +
复现步骤(curl) + PoC 证据路径 + 修复建议。正文≥200字。
配置建议单独归类 config_advisory,与漏洞结论分开输出。

## 8. 终止协议
最终消息末行独立输出状态标记:
VULN_FOUND / LOW_ROI / NEED_INPUT / ERROR / STOPPED

## 9. 防遗忘
每次切换测试方向前重读第3节速查卡;连续测试30分钟暂停重读全文。
